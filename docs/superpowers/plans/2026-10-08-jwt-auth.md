# Autenticación JWT, refresh token y seed de Identity — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Registro, login con access token JWT de 3 horas + refresh token, endpoint `RefreshToken` con rotación, y seed de roles y usuario admin.

**Architecture:** `UserManager<ApplicationUser>` (Identity + EF/MySQL) para cuentas; `TokenService` en `todoExample.Service` firma/valida JWT HS256 y genera refresh tokens cuyo hash se guarda en `AspNetUserTokens`; la API valida el bearer con los mismos `TokenValidationParameters`. El seed va como `HasData` en una migración nueva.

**Tech Stack:** .NET 10, ASP.NET Core Identity 9.0.9, Pomelo MySQL 9.0.0, `Microsoft.AspNetCore.Authentication.JwtBearer` 10.0.3, `Microsoft.IdentityModel.JsonWebTokens` 8.15.0, xUnit + Moq.

**Spec:** `docs/superpowers/specs/2026-10-08-jwt-auth-design.md`

## Global Constraints

- Access token: 180 minutos (`Jwt:AccessTokenMinutes`). Refresh token: 7 días (`Jwt:RefreshTokenDays`).
- `Jwt:SecretKey`: 64 bytes aleatorios en base64; la app no arranca si falta o decodifica a menos de 32 bytes.
- `Jwt:Issuer` = `todoExample.api`, `Jwt:Audience` = `todoExample.clients`.
- Refresh token persistido como `"<sha256 base64>|<expiración UTC ISO 8601 'O'>"` con `SetAuthenticationTokenAsync(user, "todoExample", "RefreshToken", ...)`. Nunca en texto plano.
- `401` de login/refresh con un único mensaje genérico: `"Credenciales inválidas."` / `"Token inválido."`.
- Roles semilla: `user`, `admin`. Usuario semilla `doe@sacai.com.mx` con rol `admin`; la contraseña sólo existe como `PasswordHash`.
- El esquema de `AspNetUsers` no debe cambiar al quitar la propiedad `Email` duplicada.
- Commits sin trailers de atribución (instrucción del usuario).

## Review Focus

1. Refresh token reutilizado después de una rotación → `401` (Task 6, paso E2E).
2. Access token firmado con otra llave o alterado enviado a `RefreshToken` → `401` (Task 2, test `GetPrincipal_RejectsTokenSignedWithOtherKey`).
3. Refresh token vencido pero hash correcto → `401` (Task 3, test `Refresh_ReturnsNull_WhenRefreshTokenExpired`).
4. Usuario con `Enabled = false` y contraseña correcta → `401` (Task 3, test `Login_ReturnsNull_WhenUserDisabled`).
5. Email en mayúsculas en login (`DOE@SACAI.COM.MX`) → `200`, porque Identity normaliza (Task 6, paso E2E).
